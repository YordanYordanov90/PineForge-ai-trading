# 61.2 — Research: Attach / Change / Detach Script

## Parent

Extends `61` (Research → Generate Pipeline) and `61.1` (No-Script Banner).

---

## Goal

Let users **attach a saved script** to a research conversation after
creation, **change** it mid-thread, or **detach** it — so research mode
can reference a specific script without requiring the user to start from
`/generate`.

---

## Problem

After 61.1 ships, the banner tells the user "no script attached" but
offers no way to fix it from within Forge. The only path is to navigate
back to `/generate`, click "Discuss with Forge", and start a new general
thread. Research mode has no script-attach affordance at all.

---

## Solution

### 1. Banner upgrade (replaces 61.1 banner)

| State | Banner content |
|-------|---------------|
| No script attached | `🧪 No script attached. [ Load from history ]` |
| Script attached | `🧪 Script: {name} · [ change ] · [ detach ]` |

- **Load from history** opens a lightweight picker (dialog or popover)
  showing the user's recent saved scripts. Reuse the data from
  `GET /api/scripts` (same as history sheet) — no new endpoint.
- **Change** re-opens the picker.
- **Detach** sets `scriptId` to `null` on the conversation, returning
  to the "no script" banner.
- Banner position unchanged from 61.1 (empty state: above chips;
  active thread: above input).

### 2. Script picker

A minimal dialog/popover listing recent scripts:

- Shows script name, creation date, starred status.
- Optional quick search/filter (reuse `filterHistoryEntries` from
  `lib/scripts/history-filter.ts` if the list is client-cached).
- Selecting a script triggers the PATCH and closes the picker.
- Max ~20 items; if the user has more, a "Search in history" hint
  linking to `/generate` history is fine for v1.

### 3. Backend: extend PATCH conversation

`PATCH /api/forge/conversations/[conversationId]` currently accepts
only `{ title }`. Extend to also accept:

```ts
{
  title?: string;
  scriptId?: number | null;  // null = detach
}
```

Validation:
- `scriptId` must be a positive integer or `null`.
- When non-null, verify the script belongs to the caller (reuse
  `scriptIsOwnedByUser` from `lib/db/agent-conversations.ts`).
- A foreign or missing script returns 403 (same as create flow).

DB helper:
- `updateConversationScriptId(userId, conversationId, scriptId)` —
  sets `script_id` column. Owner-scoped WHERE, no cross-user writes.

### 4. Streaming route — no change needed

`app/api/forge/route.ts` already reads `conversation.scriptId` on every
turn via `loadScriptContext`. Changing the column mid-thread means the
next message automatically picks up the new (or removed) script context.

### 5. Client wiring

- `useForgeConversations` gets a new `updateScriptId(conversationId,
  scriptId)` method that PATCHes and updates local state.
- `ForgeChat` receives a callback for script attach/change/detach and
  passes it to the banner component.
- After a successful attach, `activeConvType` stays `'research'` — only
  the `scriptId` changes.

---

## Out of Scope

- Extending this to general chat (future follow-up).
- Full history sheet inside Forge (the picker is deliberately minimal).
- Attaching multiple scripts to one conversation.
- Auto-attaching the seed script on "New Research" click (explicit user
  action via the banner is the chosen UX).

---

## Success Criteria

- Research thread with no script → banner shows "No script attached"
  with "Load from history" action.
- Click "Load from history" → picker opens with recent scripts.
- Select a script → conversation updates, banner switches to
  "Script: {name} · change · detach".
- Next Forge message in that thread → model receives the script context
  in the system prompt.
- Click "detach" → `scriptId` set to null, banner returns to
  "No script attached".
- Click "change" → picker re-opens, selecting a different script works.
- Ownership enforced: cannot attach another user's script (403).
- `npm run build` passes.
