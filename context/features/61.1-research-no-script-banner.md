# 61.1 — Research: No-Script-Attached Banner

## Parent

Extends `61` (Research → Generate Pipeline).

---

## Goal

Make it immediately visible when a Forge Research conversation has **no
script attached**, so the user is never surprised by missing context.
Provide a clear hint about how to attach one (directing to `/generate`).

---

## Problem

When a user arrives at `/forge?scriptId=<id>` and clicks "New Research",
the seed script is silently dropped. The conversation starts without
script context, but nothing communicates this. The same gap exists for
any research thread started cold from the sidebar — the user may expect
Forge to "know" their current script, but it doesn't.

---

## Solution

Add an **informational banner** inside the Forge chat area for research
conversations that have no `scriptId` attached. The banner:

- Appears **always** in research conversations with `scriptId === null`,
  regardless of how the thread was started (sidebar click, cold start,
  or post-seed-banner).
- Shows a short message: e.g. *"No script attached to this research
  thread. Start research from /generate to include script context."*
- Is **not dismissable** — it reflects real state, not a one-time notice.
  It disappears only when a script becomes attached (phase 2, spec 61.2).
- Uses the existing amber/informational styling (same family as the
  research pre-fill banner on `/generate`).

### Banner position

- **Empty state** (no messages yet): above the suggestion chips / empty
  state illustration, inside the scroll area.
- **Active thread** (messages present): slim pill pinned above the input
  area, below the message list, so it's visible without scrolling.

### When the banner does NOT show

- General conversations (`type === 'general'`) — out of scope per
  decision; general chat gets its own treatment later.
- Research conversations that **have** a `scriptId` — the existing
  `SeedScriptBanner` or the future "attached" indicator (spec 61.2)
  covers that.

---

## Affected Files

Modified:
- `components/forge/ForgeChat.tsx` — conditional banner render based on
  `isResearchConv && !conversation.scriptId`

New:
- None expected (inline JSX or a small `<ResearchNoScriptBanner />`
  extracted if it exceeds ~20 lines).

---

## Out of Scope

- Attaching a script from the banner (that is spec 61.2).
- Showing a similar banner in general chat threads.
- Any backend changes — this is purely UI/informational.

---

## Success Criteria

- Research thread started from sidebar → banner visible immediately.
- Research thread started while `/forge?scriptId=<id>` seed banner was
  showing → banner visible (script is not silently carried over).
- Research thread with `scriptId` present → banner does NOT appear.
- General chat threads → banner does NOT appear.
- `npm run build` passes.
